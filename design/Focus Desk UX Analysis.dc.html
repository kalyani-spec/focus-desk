Focus Desk · UX analysis · 22 Oct 2026

What works, what will break, and what to fix first

A review of the hi-fi prototype (Focus Desk Prototype) against one person’s working day: a product manager running four projects, logging her own time, and protecting focus. Findings use Nielsen’s heuristics plus a walk-through of the five core flows.

The verdict

The core loop — pick a task → focus → session logs itself → timesheet fills itself — is strong and rare. Most tools make you choose between a to-do app and a time tracker; this one makes tracking a by-product of focusing. The main risks are not visual. They are data trust (are my hours right?), scope creep in Projects (checklists, documents and dates are three overlapping lists), and timer edge cases (what happens when I forget, switch tasks, or get interrupted).

Who it’s for, and the jobs it must do

Protect deep workStart a focused block in one click, from anywhere, and not be pulled out of it.
Know what’s nextSee today’s few tasks across four projects without project-switching tools.
Account for timeProduce an honest weekly timesheet with near-zero manual entry.
Keep projects healthySpot slipping phases, missing sign-offs and clashes with holidays before a client does.

Strengths to protect

  1. Time tracking as a side effect. Ending a focus session writes the log entry. This is the product’s moat; never make logging a separate chore.
  2. One hero per screen. Today leads with the timer; Projects with health; Timesheet with the grid. Hierarchy is clear at a glance.
  3. Progressive disclosure. Done tasks hide behind “+ 2 done”, task details open in a drawer, checklist phases collapse except the current one.
  4. Recovery paths. “Forgot to start? Log time”, gap detection in Day view, and the clock-out review all catch missing time before it hits the timesheet.
  5. Holidays as first-class data. One list drives timeline shading, timesheet targets, milestone warnings and date pickers — no double entry.

Issues, by severity

High

H1 · Switching task mid-session is undefined

Clicking “Focus on this task” while a session runs silently restarts the timer, and the time already spent is lost. Fix: ask “Log 12m to PRD: recurring giving and switch?” with Switch / Cancel; default to logging. Heuristic: error prevention.

High

H2 · No way to edit or delete a logged session

The session log and Day view are read-only. One wrong project tag and the timesheet is wrong forever. Fix: click a session → inline edit (times, project, task), split, delete with undo toast. This is what makes users trust auto-logged hours. User control & freedom.

High

H3 · Checklist, documents and dates overlap

“Design sign-off” can be a checklist item, a document and a date. Users won’t know where to put it, and counts drift. Fix: one rule — checklist = things you do, documents = artefacts that need approval, dates = calendar events. Let a checklist item link to a document (“needs doc”) and a due date, instead of duplicating. Show the rule as helper text in each empty state. Consistency & standards; recognition over recall.

High

H4 · Destructive actions have no undo

The ✕ on checklist items, documents, dates and holidays deletes instantly. Fix: remove + “Undo” in the existing toast for 5 seconds. Cheap, and covers every list. User control & freedom.

Medium

M1 · Today still asks a lot of the eye

Coming-up chips, timer, My day, quick-add, From earlier, four project cards and a session log compete. Fix: collapse the session log by default to its last 3 entries; merge “From earlier” into the morning triage (wireframe 2f) so it’s usually empty by mid-morning.

Medium

M2 · Quick-add can’t set priority, estimate or date

Every new task is “Medium · 30m · Today”. Fix: reuse the checklist syntax from the wireframes — !high, ~1h, @fri, #stax — parsed into chips as you type. One grammar across the app.

Medium

M3 · Interruptions aren’t modelled

A PM gets pulled into calls. Pause works, but the paused minutes vanish from the record. Fix: on resume, offer “Log the 15m pause as Meeting · Surviant – General?”. Over a week this is the difference between 72% and a believable focus ratio.

Medium

M4 · Timeline is view-only

The ⚠ “QA starts on Diwali” warning has no action. Fix: click a milestone → move to next working day, with a preview of what shifts.

Medium

M5 · Status pills on documents cycle blindly

Click-to-advance is fast but you can’t go back a step without looping through Missing. Fix: small menu on click (Missing / Draft / In review / Approved) with the next state pre-highlighted.

Low

Smaller refinements

  • Handwritten Kalam on task titles is charming but slower to scan at 15+ items; keep it, but offer a “plain font” toggle in Appearance.
  • Priority is a 6px dot only; add a text label on hover and in the drawer header for colour-blind users.
  • Keyboard: add N new task, F focus, Space pause, L log time. Esc is the only shortcut today.
  • Browser tab title should show the countdown so focus survives tab switching.

Flow walk-throughs

Start a focus block2 clicks from Today, 1 from the sidebar mini-timer. Good. Missing: picking the task inside focus mode when the current one is wrong.
Finish a sessionEnd → break screen → rating → next. Clear and calm. The rating needs a visible payoff (e.g. “Deep focus mornings: 4 this week”) or users will stop answering.
Fix missing timeThree entry points (link, Day-view gap, clock-out review) all open the same dialog with the gap pre-filled. Strong. Add validation for overlaps with existing sessions.
Check a projectCard → Overview answers “are we OK?” in one screen. Tabs give depth. The card should surface the single worst thing (e.g. “UAT sign-off missing”) rather than four equal numbers.
Plan a day offAdd day off → clash warning → shows everywhere. Missing: one-click “move clashing items to next working day”.

Accessibility check

  • Navy on paper and periwinkle on charcoal both clear 4.5:1 for body text; the light accent-400 priority dot does not — fine as a non-text mark only.
  • Drawer and dialogs close on Esc and backdrop; they still need focus trapping and focus return to the trigger.
  • Timer countdown needs aria-live="polite" on minute changes only, never every second.
  • Holiday amber relies on colour plus a label — keep both.

Recommended order of work

  1. Trust in hours: H2 edit sessions, H1 safe task-switch, M3 interruptions.
  2. Safety net: H4 undo everywhere.
  3. Project model: H3 the checklist / document / date rule and linking.
  4. Speed: M2 quick-add grammar, keyboard shortcuts.
  5. Calm: M1 Today reduction and morning triage.

Open questions

  • Is the timesheet for you only, or submitted to someone who approves it? Approval changes the edit rules after submit.
  • Do tasks come from Jira or another tracker? If so, the to-do list should mirror, not duplicate.
  • Is “day span” used for anything formal (attendance, payroll), or is it a personal signal?
